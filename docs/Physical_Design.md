# Physical Design

## 1. Overview

The synthesized ASIC was implemented as a routed pad-level design using Cadence Innovus in a TSMC 65 nm low-power standard-cell flow.

The implementation includes:

```text
Initialization
    |
    v
Floorplan + Pad Integration
    |
    v
Power Planning
    |
    v
Placement
    |
    v
Clock-Tree Synthesis
    |
    v
Routing
    |
    v
Post-Route Optimization / ECO
    |
    v
Parasitic Extraction
    |
    v
Final Implementation Checks
```

![Final routed ASIC layout](../Figures/final_layout.png)

## 2. Design Handoff and MMMC

Innovus is initialized from the synthesized netlist, timing constraints, pad-level top module, I/O placement data, technology setup, and MMMC timing environment.

The implementation uses separate setup and hold analysis views, with slow conditions used for setup-oriented analysis and fast conditions used for hold-oriented analysis.

All functional sequential logic remains in the external high-frequency clock domain. The RTL's lower-rate behavior is represented by clock enables and multicycle constraints.

Implementation scripts are organized under:

```text
Innovus/scripts/
```

The directory contains the main flow and stage-specific scripts for initialization, floorplanning, power connectivity, placement, CCOpt/CTS, routing, repair/ECO, extraction, reporting, power, and LVS-netlist generation.

## 3. Floorplan and Pad Integration

The final physical dimensions are:

| Physical Metric | Result |
|---|---:|
| Die size | **1000 × 950 µm** |
| Die area | **0.950 mm²** |
| Core size | **646 × 596 µm** |
| Core area | **385,016 µm²** |
| Primary I/O ports | 36 |

The pad-level design contains the interpolation core together with the I/O pad ring.

## 4. Power Distribution

The power-delivery network was created before standard-cell placement and routing. The implementation includes core supply rings/straps, standard-cell rail connections, and the required pad-to-core power connectivity.

Power-rail behavior was later evaluated using the implemented VDD/VSS network. The rail analysis is discussed in [Power Analysis](Power_Analysis.md).

## 5. Placement and Clock Tree

Placement and pre-CTS optimization were followed by Cadence CCOpt clock-tree synthesis.

Final implementation checks report:

- no unplaced instances,
- 1,063 clock sinks,
- 10 clock buffers,
- 37 clock-gating elements,
- approximately 13.10 mm of routed clock wire.

The final timing result is taken from PrimeTime post-layout analysis rather than from an intermediate CTS report.

## 6. Routing and ECO Closure

After CTS, signal routing and post-route optimization were performed. ECO iterations were used to repair remaining timing and implementation issues.

The final Innovus checks report:

```text
Placement        : PASS
Connectivity     : no problems or warnings
Innovus DRC      : 0 violations
```

The final routed implementation is therefore clean under the Innovus placement, connectivity, and implementation-level DRC checks used by the project.

## 7. Parasitic Extraction

Separate post-route parasitic files were generated for final static timing analysis:

```text
top_slow.SPEF
top_fast.SPEF
```

These SPEF files are consumed by Synopsys PrimeTime for the final setup and hold analysis.

## 8. Final Physical Outputs

Important physical-design outputs include:

```text
top_final_final_lvs.v   # final post-layout Verilog representation
top_slow.SPEF           # slow-RC extracted parasitics
top_fast.SPEF           # fast-RC extracted parasitics
```

The final GDS is used for Calibre physical verification but is not required as a public GitHub artifact.

## 9. Innovus Repository Organization

```text
Innovus/
├── datain/
│   └── saif/
├── scripts/
├── reports/
├── power/
├── dataout/
└── work/
```

`datain/saif/` receives the mode-specific SAIF files generated by the separate top-level `SAIF_Generation/` flow. Generated databases and large temporary tool data under `work/` should remain excluded from version control.

Post-route power methodology and results are documented separately in [Power Analysis](Power_Analysis.md). Final PrimeTime, DRC, LVS, LEC, and pad-level GLS results are summarized in [Signoff](Signoff.md).
